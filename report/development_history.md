## 从摄像头改为文件输入

摄像头没有形成稳定实时更新的证据后，需求改为离线视频分析。当前版本删去实时采集链路，保留已经打通的显示和图像处理部分。厂商摄像头初始化表、教学 PDF 和未确认许可的原始资料不收入公开仓库。历史 camera_trial 只保留自写数字逻辑和诊断思路，不提供可直接承诺可用的摄像头交付包。

## 从整帧重复取邻域到流式窗口

旧加速器先接收整帧，再重复读取邻域。当前版用两行缓存和相邻窗口复用，四级弹性运算流水在背压时整体暂停。外部输入输出格式、图像大小和零边界规则保持一致。相同六组测试下平均事务周期由 171279 降到 25367；这包含测试平台的输入暂停和输出背压，不是整机软件耗时。

## 从 PS 画完整画布到 PL 原生界面

原版每帧传输 640×360 灰度画布，即 230400 字节。当前版传输两个 128×128 图像和 1024 字节元数据，共 33792 字节。PL 根据位置生成放大图像、字符、边框和曲线，再输出 720p。资源节省来自表示方式改变，而不是降低算法输入分辨率；两版算法都使用 128×128。

## 失败与修正

1. 双缓冲读出写法最初未正确推断块 RAM，LUT 用量超出预期。改为两组独立同步读寄存器，再在寄存器后选择。
2. 仅按亮度降低阈值会引入背景伪边缘。开发集上改为结合高梯度分位数和噪声梯度中位数，之后冻结参数再运行保留测试集。
3. 只与固定阈值比较不能隔离 FFT 的作用，因此加入时域组和去掉 FFT 的空间策略组。
4. 两次十分钟播放均出现一次长停顿。内存预加载没有单独消除问题；加入逐帧时间记录，定位到一次约 315 ms 的提交/等待。
5. 板上完整循环垃圾回收约耗时 197 ms。采用播放前回收、有限播放段暂停自动循环 GC、退出恢复原状态；最终十分钟测试未出现同级长停顿。
6. 干净构建时，外部 Python 被 Vivado 的环境变量污染，出现 SRE module mismatch。以 `-I` 隔离环境后，配套清单导出通过。

以上协作过程可在 `report/llm/transcript_redacted.jsonl` 中按公开消息核对。推断和当时的假设保留为历史记录，最终功能以板测输出和校验结果为准。

历史目录不参加当前默认构建。`src/history/index.json` 记录原文件与公开文件的哈希；存在隐私路径或旧编码的历史文件已脱敏或转为 UTF-8，因此两种哈希可能不同。当前正式 RTL 和 PS 代码则保持已验证版本的原字节。
